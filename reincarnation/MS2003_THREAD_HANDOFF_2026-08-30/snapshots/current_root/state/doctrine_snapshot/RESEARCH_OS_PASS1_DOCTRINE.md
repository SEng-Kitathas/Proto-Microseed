## Method-layer identities
- HSP = whole R&D operating system / topology.
- Loop+ = deep research and problem-space expansion; widens rivals, donors, assumptions, discriminators; no promotion authority.
- OARR = bounded adversarial culling (`Oops, All Red Rangers`). Named discriminator before action; attack flattering interpretation; preserve negative evidence and UNKNOWN; route-kill/switch after repeated non-informative acquisition failure; hard stop. Maximum five Rangers/steps per OARR slice; no quiet sixth Ranger.
- PDVER = Probe → Derive → Verify → Embody → Recurse. Metabolism, not final approval ritual.
- Research Arm = non-authoritative candidate evidence generator.
- Embodiment Arm = executable/physical evidence generator where reality can hurt the claim.
- Semantic Helix = local scar/result → next local mechanism question. Not global scheduling.
- Attention Reservoir = portfolio/breadth selector. Tracks OPEN / SELECTED / DEFERRED / dormant / competing high-information discriminators. The locally obvious next question is not automatically the globally best next move.
- Genome / CSC = project-aware shadow assurance/discrimination machinery: obligations/genes, project profiles, target-aware gates, lineage anchors, discrimination fixtures, known-good/known-bad/near-miss/false-positive cases, audit findings. Default ceiling: `audit_only`; veto=NONE; enforcement=NONE; promotion=NONE unless explicitly earned. A clean CSC report is not independent proof.

## Campaign law
Default campaign cadence = 20 bounded passes unless explicit project/user authority changes it. Historical 25-pass campaigns remain history and are not silently rewritten.

Each pass must:
1. state the current discriminator;
2. perform one bounded evidence-changing operation;
3. inspect the result;
4. classify evidence;
5. update hypotheses/scars;
6. identify the next discriminator revealed by the result;
7. run an Attention Reservoir breadth check;
8. stop if a boundary/hard-stop is reached.

The next pass answers the question created by the previous pass. No prewritten architecture story.

Anti-rabbit-hole check after every pass:
- still highest information gain?
- route non-informative?
- sibling hypothesis now stronger?
- branch saturated?
- polishing rather than discriminating?
- harness/evaluator failure rather than mechanism failure?

## Significant execution law
For significant runs use a durable launcher/wrapper with explicit cwd/environment/config, start/end timestamps, command line, stdout/stderr capture, exit code, PID when relevant, stable log names, and completion receipt. Inspect logs/output/exit before counting evidence.

Failure classes include PASS, NEGATIVE, UNKNOWN_INCOMPLETE, STALLED_ROUTE, HARNESS_FAILURE, INSTRUMENTATION_FAILURE, ENVIRONMENT_FAILURE, ASSURANCE_FRONTIER.
