## New project-local law: STANCE_MATCH != MECHANISM_VERIFIED
When a test or gate is intended to verify a specific producing mechanism, asserting only the final stance/status/token is insufficient if another branch can emit the same token.

Mechanism-bearing tests should, where the implementation already exposes them, assert discriminating observables such as:
- `reason`;
- exact or minimally sufficient `premise_ids`;
- binding/currentness ancestry;
- relevant epoch identities;
- evidence lineage;
- authority qualifiers;
- exact failure/rejection owner.

Do not overfit tests to incidental formatting or implementation order. Assert the minimum mechanism witness that distinguishes the intended guard from plausible substitute branches.

## Scar authority re-earning
A scar is not timeless authority merely because it was written in an earlier campaign.

At campaign open/close, scars materially relied upon by the campaign must be classified:
- CURRENT_REEARNED: discriminator survived a current campaign-specific hostile/mutant;
- INHERITED_VERIFIED_BY_CURRENT_OWNER: current exact owner/test still provides a discriminating witness and was re-run;
- INHERITED_UNVERIFIED: historically useful scar not re-earned in the current campaign;
- SUPERSEDED / DEMOTED: stronger evidence defeats or narrows it.

`INHERITED_UNVERIFIED` scars remain valuable hypothesis/hostile-test prompts but must not silently function as current proof.

## Independent grading lane
For significant campaign boundaries, prefer at least one validation lane that is not generated from the same immediate implementation reasoning. Acceptable lanes include, in descending independence:
1. external human/agent evaluator supplying mutants/counterexamples;
2. separately prompted/model-isolated adversarial grader with no implementation-plan context;
3. mutation generation from scar/contract surfaces rather than code-author reasoning;
4. literature-derived discriminators not already encoded in the local campaign.

Same-author extra tests are still useful but do not count as an independent epistemic vote merely by quantity.

## External-contact / Loop+ requirement
Microseed campaigns must periodically contact relevant external literature/prior art—not to import architecture by prestige, but to quarry:
- rival mechanisms;
- known failure modes;
- established terminology;
- discriminators/benchmarks;
- evidence that a local claim is novel, rediscovered, or already refuted.

External literature remains donor evidence, not project authority. Project-local code and experiments still decide embodiment.

At minimum, before major promotion/campaign close involving epistemic action, active experimentation, intrinsic motivation, or developmental autonomy, perform a bounded literature map and record:
- nearest conceptual neighbors;
- important differences;
- unresolved novelty claim;
- at least one imported hostile discriminator if useful.

## Method-apparatus budget check
At Reservoir closeout, explicitly ask whether methodology/documentation cost is consuming more research budget than the next discriminator warrants. Preserve auditability, but do not add artifacts/naming layers unless they buy lineage, discrimination, recovery, or authority clarity.

## Validation workflow amendment
For a claimed mechanism guard:
1. state the guard and its discriminating witness;
2. construct/delete/mutate the guard while preserving alternate branches where possible;
3. require the intended test to fail for the intended reason;
4. if it survives, classify the prior test as mechanism-blind;
5. strengthen the test before changing production code unless a genuine production hole is independently shown;
6. rerun surviving mutants;
7. only then decide whether production repair is needed.
