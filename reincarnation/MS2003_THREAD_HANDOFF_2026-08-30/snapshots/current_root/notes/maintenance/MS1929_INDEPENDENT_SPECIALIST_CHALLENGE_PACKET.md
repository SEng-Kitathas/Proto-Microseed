## System X — mechanism description
System X is a small developmental cognitive runtime with these claimed design properties:

1. Capabilities can be acquired/qualified and composed over time rather than all being supplied as one monolithic planner/policy.
2. Capability existence or feasibility does not itself authorize execution.
3. A proposed action/program may be represented without execution authority.
4. Current action authorization depends on several separately derived premises, including current capability qualification/epoch, current control-state evidence, action/consequence ancestry, operational scope, a regulatory/priority premise, and an information/discrimination premise when action is epistemic.
5. Those premises are rebound/rederived at execution time; nomination-time permission or historical permission does not automatically remain current.
6. Missing/stale premises produce explicit UNKNOWN/ABSTAIN rather than confidence-based fallback.
7. Observed outcomes are kept distinct from predictions. A successful execution does not make its prediction true.
8. Evidence/provenance/derivation history is explicit and may affect whether a learned relation is current enough to participate in later action authorization.
9. Completed information-seeking experiments can produce bounded evidence/revisit pressure without automatically producing an answer, model truth or new execution authority.
10. Historical state may be reconstructed after restart without automatically restoring current providers/contracts/action authority.
11. The architecture intentionally avoids installing one generic planner, general normative manager, global curiosity scalar or self-certifying world model as the organism’s central executive.
12. Information value can help characterize an experiment, but uncertainty/informativeness alone does not create normative permission to execute an otherwise unrepresented route.
13. An optional equipped/federated design branch has been proposed in which an external, separately qualified, one-use experiment warrant could authorize one bounded intervention; this would remain explicit assistance rather than autonomous exploration authority.

## Questions to answer

### Q1 — nearest architecture-level prior art
Identify systems that already combine the largest subset of the properties above.
Do not list only one-property analogues.
Prioritize cognitive architectures, agent architectures, safety/runtime-governance systems and proof/authorization systems that combine several relevant mechanisms.

### Q2 — learned consequence ancestry as authorization premise
Is there prior art where learned/updated action-outcome models or evidence lineage directly participate in whether the agent is presently authorized/permitted to execute an action, rather than merely influencing predicted utility or plan choice?
If yes, provide exact sources/mechanisms.

### Q3 — local owner composition versus manager
Does distributing premise derivation across local typed mechanisms create any causally distinct behavior compared with a global reference monitor/normative manager that receives the same state and computes the same decision relation?
If not, state that clearly and identify what architectural properties, if any, remain scientifically meaningful.

### Q4 — developmental/minimality distinction
Are there established architectures where action models, constraints/permissions and competence are learned/acquired developmentally while authorization remains conservatively factorized and currentness/provenance-sensitive?
If yes, identify them.
If the closest systems rely on a plan library, policy manager, scalar reward or global world model, explain whether that is a substantive mechanism difference or merely a design choice.

### Q5 — abstention and authority
Is explicit abstention because authority/provenance/currentness is incomplete materially different from classical reject-option/selective classification, runtime safety filters, deontic/normative agents or policy enforcement points?
Give the strongest counterargument.

### Q6 — exploration authority
Can any established safe-exploration/active-learning/developmental-robotics framework justify an action in an unrepresented state without importing a prior utility/reward/safety/normative objective?
If yes, state the exact normative source of permission.
If no, say whether System X’s refusal to infer permission from uncertainty is simply a conservative policy rather than a novel mechanism.

### Q7 — proof-carrying / runtime-governance equivalence
Compare System X against:
- complete mediation / reference monitors;
- proof-carrying authentication/authorization/code/plans;
- runtime assurance/Simplex;
- normative BDI/BOID;
- adaptive BDI;
- provenance/TMS/ATMS;
- contemporary proof-carrying agent-action / runtime-governance systems.
Which claimed distinctions survive those comparisons?

### Q8 — novelty verdict
Choose exactly one:
- `ESTABLISHED_ARCHITECTURAL_PRIOR_ART`
