# Scars and Do-Not-Reintroduce List

Date: 2026-08-30 ET
Purpose: preserve the engineering boundaries that were earned by failure, mutation, hostile tests, or explicit constitutional review.

A future thread SHALL read this before proposing new architecture.

This is not a list of permanently forbidden concepts. It is a list of things that SHALL NOT be reintroduced casually, silently, or under a new name without first defeating the evidence that caused their removal/bounding.

## 1. Do not reintroduce a semantic token registry to solve signaling/reference
The project already earned:
- `SIGNAL != REFERENCE`;
- `TOKEN_EMITTED != TOKEN_MEANS`;
- `COUNTERPARTY_HANDLE != SEMANTIC_OTHER_IDENTITY`;
- `REGULATORY_BEARING != SEMANTIC_MEANING`.

A signal can be operationally useful without meaning what a human label says it means.

Do not add token semantics because a useful signal-response pattern appears.

Future language scar:
`UTTERANCE_PRODUCED != REFERENT_BOUND`.

## 2. Do not reintroduce caller-selected preferred actions/programs
MS1996 specifically removed this assistance.

Do not let campaign/harness code supply:
- preferred action;
- preferred program sequence;
- “correct” candidate;
- first-choice tie-break.

If multiple current epistemic opportunities are equally supported, preserve the tie:
`MULTIPLE_CURRENT_EPISTEMIC_OPPORTUNITIES`.

Do not choose first for convenience.

## 3. Do not reintroduce evaluator-mode labels into organism-facing learning
MS1998 removed P/N evaluator mode from training guidance.

Campaign code may configure external reality for testing, but the organism-facing evidence/guidance SHALL NOT receive the hidden evaluator label unless a future experiment is explicitly about supplied context and names that assistance.

`EVALUATOR_KNOWLEDGE != ORGANISM_EVIDENCE`.
