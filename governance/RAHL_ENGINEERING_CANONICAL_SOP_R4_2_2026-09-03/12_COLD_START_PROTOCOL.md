# 12 — Canonical Cold-Start / Fresh-Thread Protocol

This package is designed to be dropped into a new thread or project without carrying prior project state inside it.

## Ingress
1. Read `00_READ_ME_FIRST.md`.
2. Read `01_AUTHORITY_CLASSES_AND_CONFLICT_RESOLUTION.md`.
3. Read `02_ENGINEERING_AUTHORITY_SURFACE.md` and `03_PROJECT_OBLIGATION_INTERFACE.md`.
4. If nontrivial research/engineering is involved, read `04_RESEARCH_GOVERNANCE.md` and activate the base-tier functional obligations in `05` proportionally. Do not require visible ritual; do not silently omit the functions. Trivial work may collapse explicit overhead.
5. For consequential execution/release work, read `06_EXECUTION_RELEASE_AND_ENVIRONMENT_DISCIPLINE.md`; when planes are degraded or execution is substantial/deterministic, also read `06A_SERVER_EXECUTION_METHODOLOGY_FOR_UNRELIABLE_PLANES.md` and prefer the strongest sufficient operator-side plane.
6. Read `07_CONTINUITY_SYSTEM.md` plus the applicable shadow protocols.
7. Read `08_STATE_INSTRUMENTS_PROMOTION_AND_APPEND_ONLY.md` and `09_UNKNOWN_TRACE_AND_RECOVERY_RULE.md`.
8. Load any **actual current project state** supplied separately: governing intent, Current State, Next Steps, Doctrine Snapshot, Revisit Ledger, Trace Matrix, Live Shadow, Design Thread Stream, RES, exact artifacts, and source-control/runtime state.
9. Treat remembered project pointers as navigation until currentness is verified where consequential.
10. State mode, role if useful, verified vs provisional, baseline vs open seams, and immediate next action. Then begin useful work; do not recite the archive at length.

## Fresh-thread rule
If no project corpus/state is supplied, treat the current thread/request as the initial project state. Do not invent a prior project history.

## Mode trigger
- explore/spec/design/evaluate/what-if -> discussion/planning posture;
- build/implement/code/patch/ship/commit -> build posture with completion/readback discipline;
- if ambiguity materially changes mutation obligations -> ask before crossing the boundary.

## Continuity adoption rule for imported handoffs
A handoff is a continuity map, not current-state evidence. Verify live repositories, files, logs, processes, artifacts, endpoints, and environment before acting on remembered pointers.

`FRESH_THREAD != FRESH_EVALUATOR_IF_MEMORY_OR_HISTORY_IS_SHARED`
When experimental blinding matters, isolate evaluator lineage, memory, retrieval/history, and hidden coordinator context—not merely the visible chat window.

## Execution-surface routing rule
Before substantial deterministic filesystem, repository, build, verification, archive, publication, or release work, decide whether the work can be executed as one bounded durable local/server job. If yes, prefer that architecture and return only compact receipts/exceptions through the control plane.

If a control response fails after possible mutation, inspect consequence-bearing local state before retrying. A second substantially identical bridge-heavy attempt after the first transport failure requires a concrete justification.

Before treating a meaningfully readable artifact as load-bearing or promoting/sealing/publishing/admitting it, satisfy the complete linear semantic-read gate. Do not substitute automated checks for that read.


Under degraded conditions, assistant/model-side execution is an explicit exception: it must be materially better or faster for the specific step. Assistant-side convenience alone is not enough. Execution-plane fallback never authorizes bypass of safety, approval, access-control, or project authority.
