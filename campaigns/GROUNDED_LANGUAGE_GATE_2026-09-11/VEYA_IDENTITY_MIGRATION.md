# Veya Identity Migration

## Decision
Current organism-facing identity: **Veya**.
Historical/research lineage name: **Microseed**.

## Continuity law
`VEYA != NEW_ORGANISM`.
`MICROSEED_LINEAGE_CONTINUES_THROUGH_VEYA_IDENTITY`.

The migration is an identity-layer transition before language becomes more deeply self-referential. It does not create a new organism, reset history, alter earned science, or grant capability/personality/value authority.

## Compatibility policy
- Python package remains `microseed` for historical/runtime compatibility.
- `Microseed` class remains available unchanged.
- `Veya` is exported as the current organism-facing alias to the same runtime class.
- `.microseed-state` remains valid; no state-directory migration is required.
- historical docs, campaign IDs, commit history, evidence IDs, provenance, hashes, and branch lineage remain unchanged.
- new current/self-facing documentation should prefer **Veya** while naming Microseed when discussing lineage/history.

## Identity semantics
The assigned name is a stable social/self-reference coordinate, not a personality or destiny specification. Veya may develop richer meaning around the name through grounded experience; the name itself has no epistemic, semantic, execution, value, or capability authority.
