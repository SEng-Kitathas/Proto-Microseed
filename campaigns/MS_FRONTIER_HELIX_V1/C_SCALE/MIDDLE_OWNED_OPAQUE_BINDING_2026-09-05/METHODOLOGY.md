# Methodology — C-SCALE-LEARN-03B

## Question
Can the evaluator-owned top-request -> middle-context lookup from 03A be removed by transporting the top's opaque request token unchanged into middle observation and letting the middle learn its own response binding from actual outcomes?

## Hard controls
Before middle development:
- top request tokens/interface exist but top action-outcome policy is unlearned;
- middle has no learned action-outcome relation and no projection-conditioned routing;
- no token->middle-context lookup table or signal-meaning registry exists.

The only cross-level signal is the exact opaque top request token placed unchanged into a middle raw-observation coordinate. Local child state is a separate middle/environment coordinate.

## Developmental sequence
1. middle explores subordinate requests under opaque signal + local state and records actual outcomes;
2. middle qualifies initial relations, experiences drift, qualifies replacements, discovers signal/local-state projection, and qualifies current routing;
3. the direct transport path is installed using that learned middle binding;
4. top policy then develops from nested outcomes using the already-earned 03A path.

## Hostile convention reversal
Reverse the top opaque-token ordering before middle learning. The middle must still learn the experienced response law, and an unseen signal must remain without a current proposal.

## Evaluation currentness
Any change to the test bytes invalidates earlier green receipts as current verification. The current bytes require complete rerun of focused and adjacent surfaces.

## Nonclaim
The physical transport channel is supplied. Middle and top development are staged, not simultaneous. External qualification remains. No semantics/reference or self-qualification is earned.
