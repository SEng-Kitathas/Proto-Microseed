# R3.1 Process Contract — MS_FRONTIER_HELIX_V1

## Required machinery
- PDVER: `PROBE -> DERIVE -> VERIFY -> EMBODY -> RECURSE`.
- Semantic HELIX: SURVIVORS / SCARS / DEMOTIONS / UNRESOLVED / NEXT.
- OARR: a real rival, removal, altered mechanism, counterexample, assistance-leak, old-owner, search-artifact, currentness, or authority-laundering discriminator where meaningful.
- LOOP+: deliberately widen to at least one adjacent plausible causal explanation before local closure where such an explanation exists.
- HSP: qualify the measurement frame before strong phenotype/mechanism claims.
- Attention Reservoir: bounded neglected evidence/branch/anomaly ledger; research governance only.
- CSC: audit-only, zero promotion authority; may block/demote claims, never select architecture.
- Assistance ledger and authority ledger are required when assistance/authority can alter the claim.

## Pass acceptance
A pass is methodologically rejected if it has no real evidence contact, generic/rhetorical OARR, trivial LOOP+, prewritten NEXT, silent authority change, UNKNOWN laundering, ambiguous execution, missing readback, or repetition without new pressure.

## Research/organism boundary
Process instrumentation, role labels, Helix state, Reservoir, CSC, OARR, and campaign scheduling are never organism/product mechanisms merely because they help research.

## Execution discipline
For consequential execution bind cwd/interpreter/environment where relevant; persist stdout/stderr/exit/completion; inspect final artifact/state; timeout/ambiguous completion remains UNKNOWN. Hashed execution evidence is preserved as exact bytes when identity matters.

## Promotion discipline
Research outcomes use: NEGATIVE_CLOSED / UNKNOWN_INCOMPLETE / RESEARCH_SIGNAL / VERIFIED_RESEARCH_RESULT / PRODUCTION_CANDIDATE / PROMOTION_READY. None is canonical. Explicit PROMOTION mode remains separate.
