# MS2058 — Hierarchy Transfer C1: Relation-Backed Candidate Identification

## Question
Can Microseed remove the externally enumerated subordinate request shortlist without adding a new selector owner, by projecting candidate identities from already-qualified current action-outcome relations and current capability/obligation/scope owners?

## Distinction
`CURRENT_COMPATIBLE_CAPABILITY_ENUMERATION != LEARNED_SUBORDINATE_RELEVANCE`.

C1 therefore does **not** scan all current capabilities and call them candidates. A capability enters the research candidate surface only when:
1. a current qualified action-outcome relation exists from the exact current opaque state for that capability;
2. the capability itself is current through dependency closure;
3. the capability owns EFFECT authority already;
4. its query obligation and operational scope match the current bounded request.

The projection grants no feasibility, truth, semantic role, qualification, ranking or execution authority. It is a research-only read of existing owners.

## Hostiles
- current capability with no learned relation is excluded;
- strong learned relation with wrong obligation is excluded;
- strong learned relation with wrong scope is excluded;
- read-only capability is excluded;
- unseen state produces no candidates;
- stale capability/relation disappears without history deletion;
- equal-positive candidates remain a set rather than arbitrary structural selection;
- no Parent/Child/topology semantic claim is created.

## Interpretation boundary
If C1 survives with zero production delta, then externally enumerated request shortlist is not a necessary mechanism for this bounded case. It does **not** solve endogenous capability invention, feasibility discovery, role topology, recursive hierarchy, or CFE transfer.

## Result

Broader recruitment/topology/action-learning/P1A/N1A/MS2057/MS2058 guard: **53/53 PASS in 27.64s**.

For this bounded case, externally enumerating U1/U2 is not required once current qualified request-effect relations exist. A read-only projection of exact-current learned relations intersected with exact-current EFFECT capability + obligation + scope owners yields the relevant candidate set while excluding unrelated, stale, wrong-scope, wrong-obligation and non-effect capabilities.

This does not assign feasibility, rank equally supported candidates, name Parent/Child roles, or grant execution authority.
