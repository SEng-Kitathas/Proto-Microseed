# MS2004 — Unified Referent Lifetime Policy

## Question
Can the existing Microseed mechanisms compose across a multi-session lifetime in one external world so that drift/relearning, restart/currentness, persisted operational referent classes, zero-row action choice, ambiguity refusal, and capability requalification all coexist without adding a new referent, policy, lifecycle, or cross-cutting manager?

## Mechanism
MS2004 composes mechanisms already earned by prior milestones rather than adding a new cognitive owner:

1. Session 1 acquires historical qualified action-outcome relations from lived P-mode outcomes.
2. Session 2 encounters N-mode drift, derives predictive-currentness failure witnesses, nominates replacements, and qualifies replacement relations from later lived outcomes.
3. Session 3 uses the same external world to produce opaque operational referent probe traces, persists operational referent signatures/class-set contexts, and externally qualifies projection-conditioned relation routing from independent holdout outcomes.
4. Session 4 restarts again, requalifies an unrelated stale capability under MS2000 rules, then supplies **zero rehearsal rows** while the current operational referent class-set context selects the already-qualified routing and action program.
5. An aliased referent surface must fail closed: no rehearsal policy is produced.

The external world owns both regulatory control outcomes and opaque referent probe channels. The caller does not supply the runtime projection bucket, referent class, or preferred action.
