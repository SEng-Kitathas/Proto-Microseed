## Non-circular exposure schedule
Experimental exposures are scheduled with deliberately wrong/non-informative one-step rehearsal predictions. The intended/supplied prediction is retained only as provenance. The action-outcome learner receives the actual observed next state/value effect.

After training/qualification, all supplied rehearsal transition rows are removed. The query surface exposes two feasible options with empty `predicted_effect` tuples. Any later context-sensitive request choice must therefore come from qualified learned action-outcome relations.

## First harness scar
Initial focused run returned **2 PASS / 4 FAIL** before any transfer assertion was exercised. `exposure_proposal()` supplied only one scheduling rehearsal observation; the existing rehearsal owner correctly requires recurrent support and returned `None`.

Classification: `MS2057_SINGLE_ROW_EXPOSURE_SCHEDULER_REJECTED_BY_EXISTING_REHEARSAL_RECURRENCE_GATE__HARNESS_ERROR_NOT_TRANSFER_FAILURE`.

Repair: use eight identical, deliberately wrong/non-informative scheduling observations per exposure. This satisfies the already-earned rehearsal recurrence floor without supplying the actual observed higher-level consequence that Experimental B is meant to learn.

## Second harness scar
After the recurrence repair, the scheduler reached the bounded-action commitment gate but correctly returned `NO_CURRENT_REGULATORY_PRESSURE`: the fixture had defined `V=0` inside a `[-10,+10]` viable interval and supplied a neutral `0` effect. Four transfer-bearing tests therefore still did not execute.

Classification: `MS2057_EXPOSURE_SCHEDULER_HAD_NO_LAWFUL_REGULATORY_REASON_TO_ACT__HARNESS_ERROR_NOT_TRANSFER_FAILURE`.

Repair: define the existing value variable viable interval as `[1,10]` with current value `0`, and give **every** scheduled exposure the same +1 predicted effect. This makes exposure lawful while remaining non-discriminating across HA/HB and U1/U2. The actual environment still supplies +2/-2 context-dependent consequences, so the scheduling model cannot encode the answer.

A direct debug invocation also encountered the known Windows SQLite temporary-directory cleanup lock after printing the authoritative abstention reason. This is cleanup noise only; scientific runs continue through `tools/run_pytest_cleanup_neutral.py`.

## Third harness scar
After lawful exposure scheduling, focused run reached **5 PASS / 1 FAIL**. The remaining failure was a test API-name mistake: `CounterfactualRehearsalProposal` exposes the selected request sequence as `sequence`, not `selected_capability_ids`. The proposal itself existed and had already reached the learned-rehearsal path.

Classification: `MS2057_TEST_ASSERTED_RECRUITMENT_FIELD_NAME_ON_REHEARSAL_PROPOSAL__TEST_API_MISMATCH_NOT_TRANSFER_FAILURE`.
