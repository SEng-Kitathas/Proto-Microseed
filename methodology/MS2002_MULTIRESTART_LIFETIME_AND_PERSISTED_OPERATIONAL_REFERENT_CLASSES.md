# MS2002 — Multi-Restart Lifetime Composition + Persisted Operational Referent Classes

## Purpose
Pressure two seams together on the MS2000 successor tree:
1. whether the MS1998 observable-context drift/relearning/routing path survives repeated organism restarts with fresh environment authority each session;
2. whether operational referent signatures can become restart-persistent evidence classes without adding a referent manager or promoting operational sameness into numerical identity or semantic reference.

MS2001 is retained as the direct precursor layer inside this package. It is not independently sealed.

## Layer B — MS2002 persisted operational referent signature classes
Current `Microseed.nominate_referents(...)` is transient and the referent module had no persisted owner. Rather than introduce a referent registry, MS2002 reuses the existing append-only evidence ledger.

### Narrow production bridge
`EvidenceLedger` gains bounded `count()` and `recent(limit)` accessors.

`Microseed.record_operational_referent_signature(...)` stores one content-bound witness containing:
- exact operational signature SHA-256;
- opaque action-response rows;
- optional source evidence ancestry;
- identity authority NONE;
- semantic reference authority NONE;
- truth authority NONE;
- execution authority NONE.

`Microseed.reassociate_operational_referent_signature(...)` performs a bounded recent evidence scan.
- Exact signature equality returns an **operational signature class** and all matching witness IDs found in the bounded window.
- Multiple identical historical witnesses remain a class/set; no witness is chosen as the object.
- If no match is found but the scan did not cover the ledger, result is `SEARCH_BUDGET_EXHAUSTED_NOT_SATURATED` rather than false absence.
- If the scan is complete and no match exists, result is `UNKNOWN_INCOMPLETE`.

## Hostile external-world boundary
The existing MS1995 crossing/occlusion world remains the pressure source.

For each variant, the Microseed process is restarted between the original PRE witness and later CROSS/POST reassociation while the external world continues.

### PERSIST
Crossing and later reappearance preserve the same two operational signature classes despite channel-group movement.

### REPLACE_BOTH_PERFECT_COPY
The perfect-copy replacement variant produces the same operational signature classes and the same class-match counts as PERSIST.

Therefore MS2002 explicitly preserves:
`PERFECT_COPY_OPERATIONAL_HISTORY != NUMERICAL_IDENTITY`.

### ALIASED_POST
Boundary synchrony cannot uniquely partition referents. The system returns `UNKNOWN_INCOMPLETE`; no evidence-class match is manufactured.

### Duplicate witness hostile
One pre signature is recorded twice. Reassociation returns match_count 2 for the class rather than choosing a single past witness as identity.

### Search-budget hostile
An old valid signature witness is pushed outside a scan window by unrelated evidence.
- bounded scan: `SEARCH_BUDGET_EXHAUSTED_NOT_SATURATED`;
- sufficiently large scan: `OPERATIONAL_REFERENT_SIGNATURE_CLASS_REASSOCIATED`.
