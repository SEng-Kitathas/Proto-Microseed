# MS2063 — End-to-End Bounded Two-Level Hierarchy Transfer Integration

## Status
BUILD-COMMIT research integration pressure. MS2062 production candidate is already whole-suite green; MS2063 initially adds no new production mechanism.

## Question
Do the independently earned MS2057–MS2062 owners actually compose into one bounded two-level developmental hierarchy loop, or were the earlier successes only isolated local demonstrations?

## Integrated specimen
One Microseed lifecycle must close all of the following without semantic Parent/Child ontology:
1. learn and externally qualify an opaque target projection;
2. bind its two learned buckets into one already-qualified request channel using MS2062 fixed-target specialization;
3. preserve child-local means outside the parent capability registry;
4. execute real bounded request episodes and let external observation own the higher-level outcome;
5. qualify actual-outcome request-effect relations;
6. expose a later context/child-state reversal, produce durable drift witnesses and fresh replacement relations;
7. derive an opaque context projection from **owned raw observation receipts joined to those same authenticated outcomes**;
8. require the projection to recover the higher-context + child-current-state pair while ignoring nuisance coordinates;
9. externally qualify projection-conditioned routing that can reuse the old relation only in its freshly qualified old bucket while leaving it globally stale;
10. at query time derive the bucket from exactly one current owned raw receipt, then let existing rehearsal select between bound request specializations with no supplied predicted effects;
11. retain subordinate REFUSED/UNKNOWN feasibility authority;
12. fail closed on unseen/ambiguous child context;
13. stale the appropriate surfaces on target projection, context projection, request-channel, or request-capability drift;
14. preserve evidence/projection/relation/routing history across restart while requiring explicit operational handler re-registration before executable request specializations are deterministically re-derived.

## World law
Raw current observation is four opaque coordinates:
`(nuisance_1, higher_context, child_current_state, nuisance_2)`.

The useful target class is evaluator-hidden XOR of higher context and child state. Neither factor alone suffices. The two nuisance coordinates vary but do not change the effect.

For each target request:
- correct target -> `HIGHER-GOOD`, +2 on V;
- wrong target -> `HIGHER-BAD`, -2 on V.

The same target is implemented by different child-local means under C0 versus C1. Those means never enter the parent CapabilityRegistry.

## Developmental sequence
### Target representation
A bounded opaque target projection is discovered and externally qualified. Its bucket tokens are the only target handles that MS2062 may specialize.

### Phase 0
Two raw higher/child contexts share one request-effect law. Actual world outcomes establish one relation per bound request specialization.

### Phase 1
Two other raw contexts reverse the request-effect law while keeping the same opaque `ALIAS` start-state. Existing relations become empirically stale; actual outcomes nominate replacement relations that require fresh external qualification.

### Context representation
The full authenticated raw-receipt/action-outcome history feeds existing projection discovery. A valid integrated survivor must recover exactly the higher-context + child-state coordinate pair, not either nuisance coordinate.

### Scoped currentness
Existing projection-conditioned relation routing is externally qualified. The old globally stale relation may be used only inside the old qualified projection bucket; it is never globally reactivated.

### Query/execution
Caller supplies raw observation only. Caller does **not** supply:
- projection bucket;
- preferred routed relation;
- preferred request target;
- predicted request effect;
- child local means.

Existing owned-raw routing + rehearsal choose the bound request specialization. Ordinary action commitment/intent/execution then closes the request, and child local control chooses its means.

## Hard falsifiers
- caller-selected projection bucket or request target after deliberation;
- supplied predicted effect at query time;
- local child means appearing as parent capabilities;
- old globally stale relation silently becoming globally current;
- target projection drift leaving request specialization executable;
- context projection drift leaving routing current;
- REFUSED/UNKNOWN child request becoming executable;
- unseen child context receiving an arbitrary fallback;
- restart restoring executable handlers without explicit re-registration;
- semantic Parent/Child, desired-state, truth, or execution authority being inferred from opaque labels.

## Interpretation boundary
A pass would establish only a bounded Microseed-native transfer survivor. It would not prove recursive hierarchy, arbitrary target construction, general planning, semantic desired-state understanding, CFE transfer, or canonical promotion.
